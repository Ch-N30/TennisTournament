# Отдельный матч — MVP

## Границы

Матчи → настройка → ведение → сохранённый результат. Турниры отложены,
их существующий код сохраняется. Профиль не обязан участвовать в матче.
Новые экраны на русском. Создание — кнопка «+» сверху справа, не вкладка.

## Правила и критерии приёмки

- Одиночный / парный состав; мужская / женская категория и парный микст.
  В миксте места каждой стороны фиксированы: мужчина, затем женщина.
- Имя и фамилия обязательны. Игроки имеют UUID; профиль привязывается
  отдельно по profileID. Совпадение имён не означает одинаковую личность.
- Снимок состава и правил фиксируется при старте. При смене категории или
  размера состава удаление заполненных несовместимых мест требует подтверждения.
- Один сет или до двух выигранных сетов. Учёт только выигранных геймов.
  Сет заканчивается при 6:0–6:4, 7:5 или 7:6 через тай-брейк при 6:6.
- Допустимый итог тай-брейка: 7:0–7:5 либо N:(N−2), где N ≥ 8,
  в любом направлении. Например, 8:4 недопустим: игра закончилась бы при 7:4.
- Решающий сет такой же; супер-тай-брейка и счёта 15–30–40 нет.
- Победный гейм/тай-брейк автоматически завершает сет и при необходимости матч.
- Последовательная отмена воспроизводит оставшуюся историю событий;
  отмена победного действия открывает матч снова, в том числе после перезапуска.

## Архитектура

Чистый Swift Domain хранит конфигурацию, историю и детерминированный счёт.
Repository — граница persistence; ViewModel публикует только сохранённые изменения.
Coordinator владеет отдельным PRNDS flow матчей. DI остаётся в composition root.

## Проверка

По явному запросу пользователя новые тесты не пишутся, существующие не меняются,
unit/UI-тесты и автоматические UI-прогоны не запускаются. Это исключение из
AGENTS.md, commands/add-feature.md и требований покрытия критических правил.
Сборка проверяет компиляцию, но не доказывает корректность поведения.
Ручные критерии: состав/смена категории, старт, 6:5 → 7:5, 6:6 → тай-брейк,
отмена через границу сета/матча, восстановление после перезапуска и ошибки хранения.
